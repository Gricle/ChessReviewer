# ChessReviewer

A browser-only chess Game Review tool (chess.com-style). Paste a PGN or import
a game from a chess.com username, and Stockfish (running in your browser)
analyzes every move: classification (Brilliant / Great / Best / … / Blunder),
accuracy %, evaluation graph, best-move arrows, and opening detection. No
backend, no accounts, no token cost.

The UI ("Nocturne") is a tabbed shell — Import / Review / Library — with
one-click sample demos, keyboard shortcuts (←/→ move, Home/End jump,
Space autoplay, F flip board), and an optional cloud library of saved
reviews, weakness reports, and accuracy trends. The UI ships in ten
languages (English, 中文, हिन्दी, Español, Français, العربية, Русский,
Português, Deutsch, فارسی) with full RTL support — switch via the globe
menu in the header.

## Develop

    npm install
    npm run dev

## Test

    npm test

## Build & deploy

    npm run build      # outputs dist/
    npm run preview    # serve the production build locally

Deploy `dist/` to any static host (Vercel/Netlify). The Stockfish engine files
live in `public/engine/` and are copied into the build automatically.

## Cloud sync (optional)

Reviews auto-save to your account when Supabase is configured; without it the
app is fully functional in guest mode.

1. Create a free project at https://supabase.com.
2. In the SQL editor, run `supabase/migrations/20260702000000_init.sql`
   (or `supabase db push` with the CLI).
3. Auth → Providers: enable Email; optionally enable Google (add your OAuth
   client, and add the app origin to the redirect allow-list).
4. Copy `.env.example` to `.env.local` and fill in the Project URL and anon
   key from Project Settings → API.

Row-level security restricts every table to the signed-in user's own rows.

## How it works

```
Import → parse PGN → analyze each position (Stockfish/WASM) → classify moves
       → compute accuracy → detect opening → render review
```

Every distinct position is evaluated once by Stockfish (MultiPV 2). A pure
assembly step then turns those evaluations into per-move classifications and
accuracies. The engine runs in a Web Worker, so the UI stays responsive.

## Notes

- Move classification uses win%-drop thresholds tuned in
  `src/analysis/thresholds.ts`. It reproduces chess.com's look-and-feel closely
  but not their exact proprietary "Brilliant"/"Miss" logic.
- The full [Lichess ECO set](https://github.com/lichess-org/chess-openings)
  (~3,800 openings) ships in `src/data/openings.ts`, generated from the source
  TSVs by `scripts/genOpenings.mjs` (`node scripts/genOpenings.mjs` to refresh).
  `src/data/openings.sample.ts` is retained only as a small deterministic test
  fixture.
- Analysis depth is set in `src/App.tsx` (`DEPTH`).
- The engine is the **single-threaded** Stockfish build, so it runs on any
  static host without cross-origin-isolation (COOP/COEP) headers.

## SEO

All public metadata lives in one file: **`site.config.json`** (origin, base path,
name, description, keywords, languages, verification tokens). It's the single
source of truth for both the app and the build scripts, so the search-facing
surface stays consistent.

- `scripts/seoShared.mjs` generates every search-facing string: the `<head>`,
  the static first-paint shell, and the no-JS landing copy. Structure comes from
  `site.config.json`, wording from `src/i18n/locales/`, so a prerendered page
  cannot drift from what React renders.
- `vite.config.ts` fills the `<!--seo:*-->` markers in `index.html` with the
  English output. **`scripts/prerender.mjs`** then runs after `vite build` and
  writes one static page per language.
- `scripts/genSeo.mjs` (runs on `prebuild`) generates `robots.txt`,
  `sitemap.xml` (with per-language `hreflang`), the PWA `site.webmanifest`, and
  `ads.txt` — all from `site.config.json`.

### One indexable page per language

English is the bare base URL; the other nine live at `<base>/<code>/` as real
static files, each with its own translated title, description, JSON-LD, landing
copy, `<html lang>`/`dir`, and a **self-referencing canonical**.

That last part is the whole point. The previous `?lng=<code>` URLs all shipped
the English canonical, so Google discarded the hreflang cluster and indexed one
page instead of ten — and the crawlers `robots.txt` invites (GPTBot, ClaudeBot,
PerplexityBot) run no JavaScript, so they saw English content at every address.
`src/config/seo.test.ts` locks the invariants down; `?lng=` still resolves so
old links keep working, and the app rewrites them to the path form.

- Landing content (features, how-it-works, comparison, FAQ) lives in the `seo`
  i18n namespace, translated into all ten languages, and is emitted into each
  page's `<noscript>` so crawlers that skip JavaScript still read it.
- `SeoHead` keeps the title/description/canonical/OG in sync when the visitor
  switches language in-app.
- The social share card is `public/og.png`, regenerated by
  `node scripts/genOgImage.mjs` when branding changes.

### Changing the domain

When the custom domain lands, edit **only** `site.config.json`: set `origin` to
the new domain and `basePath` to `"/"`. Everything (canonicals, sitemap,
manifest, `ads.txt`, `hreflang`) regenerates from that on the next build. Also
update `base` handling in `vite.config.ts`/`404.html` if moving off the GitHub
Pages sub-path.

### Go-live checklist

1. Deploy, then submit `sitemap.xml` in **Google Search Console** (on a project
   sub-path, `robots.txt`/`ads.txt` aren't at the domain root, so submit the
   sitemap URL directly). Paste the verification token into
   `site.config.json` → `verification.google`.
2. Repeat for **Bing Webmaster Tools** (`verification.bing`).
3. A custom root domain is strongly recommended for both ranking and AdSense.

## Ads (AdSense-ready)

The ad system in `src/ads/` is fully built but **dormant** until a publisher ID
is supplied — the app is 100% functional with ads off.

To activate:

1. Get approved for Google AdSense (needs the SEO content and privacy policy
   live first — both ship here).
2. Set `VITE_ADSENSE_CLIENT=ca-pub-XXXXXXXXXXXXXXXX` (build env / GitHub secret).
   `ads.txt` then auto-fills your real publisher line on build.
3. Fill the numeric slot IDs in `src/ads/adsense.ts` (`AD_SLOTS`).

Consent is handled via **Google Consent Mode v2** — ad/analytics storage
defaults to denied, a banner gates loading, and the AdSense script only loads
after "Accept". For EEA/UK personalized ads, also enable a Google-certified CMP
via **Privacy & messaging** in your AdSense account. A privacy policy lives at
`public/privacy.html`, linked from the footer and consent banner.
